# tickacct: tick/switch CPU-time accounting (2026-08-09)

Feature-gated refactor (`tickacct`, off by default) that moves utime/stime
accumulation off the per-syscall `TimeManager::poll()` and onto timer ticks +
context switches — Linux `TICK_CPU_ACCOUNTING`. Implemented, adversarially
reviewed (15-agent + 4-agent workflows), two HIGH bugs fixed, re-verified.

## Motivation and the honest perf reality

`set_timer_state` ran `poll()` at **both** syscall boundaries (entry→Kernel,
return→User). `poll()` = clock read + itimer scan (×2–3 `update_itimer`) +
signal-emission closure + utime/stime accumulation. Bisect (board): removing the
whole `set_timer_state` was −250 ns on getpid; isolating just the two `poll()`s
was ~−210 ns (getpid 900→690).

**But 690 ns required skipping accounting entirely — which is incorrect.** The
adversarial review proved that skipping `poll()` unconditionally mis-attributes
the user/kernel split and staled the readers (see below). The correct version
does a cheap `tick()` at the boundary instead of `poll()`. Since `tick()` and
`poll()` both retain the (dominant) clock read, the real saving is only the
itimer scan + closure — **tens of ns/syscall, not ~210**. The board A/B will
give the exact number.

So tickacct is a **modest** syscall speedup plus two correctness properties:
1. **Uniform all-CPU periodic accounting.** Before this, the per-tick
   `tick_cpu_time(current())` callback (proc.rs) was registered **only on the
   boot CPU** (`TIMER_CALLBACKS` is per-CPU). Tasks on CPU1–7 had **no** periodic
   CPU-time accounting — utime/stime only advanced at their own syscall
   boundaries. `on_tick` fixes that on every CPU.
2. **Exact split preserved** at ~clock-read cost (see FIX B).

The big syscall-gap levers (check_signals, dispatch, the SVC round-trip, the
~5 µs pipe path) are elsewhere; tickacct is not the headline win. It is a
correct, gated, low-risk improvement — kept off by default pending (a) a
compelling board number and (b) the SMP-safety prerequisite below.

## Design (feature `tickacct` → `ax-task/task-tick-hook`)

`TimeManager` already carried **two independent baselines** (`last_tick_ns` for
`tick()`/utime-stime, `last_wall_ns` for `poll()`'s itimer_delta), built so
tick() and poll() coexist without double-counting — CPU0 already ran both today.
The refactor just adds the missing call sites + a gate:

1. **Per-tick, all CPUs** — new `TaskExt::on_tick` (axtask), called from
   `on_timer_irq` (every CPU) → `Box<Thread>::on_tick` → `time.tick()`.
2. **Per-switch** — `on_leave` → `time.tick()` (bill the outgoing slice before
   it leaves the CPU); `on_enter` → `time.retick()` (reset the baseline to the
   resume point so the descheduled gap is not billed).
3. **Per-boundary** — `set_timer_state`: `if has_armed_itimer() { poll() } else
   { tick() }; set_state()`. The cheap `tick()` bills the outgoing state's slice
   before the flip (exact split + fresh readers); the full `poll()` runs only
   when an itimer is armed.

Every wall-ns is billed exactly once: `tick()`/`poll()`/`retick()` all advance
`last_tick_ns`, so each `[last_tick..now]` interval is consumed by exactly one
of them (or intentionally discarded by `retick`). The itimer clock
(`last_wall_ns`) is a separate baseline → no cross-contamination.

OFF path is **byte-identical** to before (verified): `poll(emitter);
set_state(state)`.

## Adversarial review (15 agents) → 5 confirmed bugs

| # | sev | bug | resolution |
|---|-----|-----|------------|
| 1/4 | HIGH | **Stale `last_wall_ns` → freshly-armed `setitimer`/`alarm()` fires immediately.** With no itimer armed, `poll()` (sole writer of `last_wall_ns`) never runs, so it freezes (0 or seconds-old) while wall time advances; the first post-arm `poll()` sees a huge `itimer_delta` and fires ITIMER_REAL/PROF on the spot. Found by 2 independent lenses. | **FIX A** |
| 3 | HIGH | **Pre-syscall user compute mis-billed to stime.** `set_state`-only doesn't bill the outgoing slice, so the user→kernel boundary interval is attributed to whatever state the next sample sees (systematic stime bias for block-heavy tasks via `on_leave` with state=Kernel). | **FIX B** |
| 5 | MED | **Readers stale up to one tick** (`CLOCK_THREAD_CPUTIME_ID`/getrusage self freeze across a sub-tick loop; OFF freshened them via the entry `poll()`). | **FIX B** (entry `tick()` freshens) |
| 2 | LOW | Cross-CPU reader holding the `time` RefCell during a switch makes `on_leave` skip → `retick` discards the sub-tick sliver (non-recoverable under-bill). Sub-tick, narrow race, **not a regression**. | accept + document |

Refuted (4): panicking-`borrow` guard already present; `on_tick` None-guards
present; the preemption-mid-borrow over-bill; the RefCell race as a
*tickacct-introduced* regression (it is pre-existing — see prerequisite).

## Fixes

**FIX A** (`timer.rs::set_itimer`): on the **disarmed→armed** transition
(`remained_ns>0 && !has_armed_itimer()` tested pre-replace), re-baseline
`last_wall_ns = now`. So the first post-arm `poll()` measures `itimer_delta` from
the arm point (~µs), not from boot. Guarded so an already-armed re-arm (where the
entry-poll already kept `last_wall_ns` fresh) is untouched. `#[cfg(tickacct)]`.

**FIX B** (`ops.rs::set_timer_state`, tickacct branch): `if has_armed_itimer() {
poll() } else { tick() }; set_state()`. `tick()` before `set_state` bills the
outgoing state's `[last_tick..now]` under the correct state → exact user/kernel
split (getpid: [t0..entry]→utime, [entry..return]→stime; blocking read:
pre-syscall user→utime, [entry..block]→stime via on_leave), and freshens the
current thread's counters for getrusage/times/clock_gettime readers.

**Re-verify (4 agents): all fixes correct**, no double-count, OFF byte-identical.
One residual LOW (cross-timer re-arm under-bill) already folded into FIX A's
guard.

## SMP-safety prerequisite — RESOLVED (commit 710eed8c3)

**Cross-CPU non-atomic RefCell race on `thr.time`** (MEDIUM, pre-existing,
*widened* by tickacct). `thr.time` was `AssumeSync<RefCell<TimeManager>>`; the
borrow flag is a non-atomic `Cell<isize>`. `alarm_task::poll_timer(T)` (CPU-A,
for an armed itimer) and cross-CPU `getrusage`/`/proc` readers could race `T`'s
own `on_tick`/`on_leave`/`set_timer_state` (CPU-B) — concurrent borrows of the
same non-atomic flag → aliasing `&mut` / spurious panic → UB.

**Fixed** by converting `thr.time` to `ax_sync::spin::SpinNoIrq<TimeManager>` (a
real IRQ- and preempt-disabling spinlock): IRQ/switch paths `try_lock` (skip on
contention, never block); task-context paths `lock()`; `poll()` returns the
fired itimer signals instead of taking an emitter, so the lock is never held
across signal delivery (single consistent nest `thr.time → ALARM_LIST`, no
cycle). Adversarially reviewed (7-agent deadlock/reentrancy/equivalence
workflow): **0 confirmed bugs**. Board-validated: both configs boot to shell and
run to completion on real 8-core (no deadlock); `rusage_acct` hammers `getrusage`
(now a lock) and PASSes.

### Honest perf update after the SMP-safe conversion

The SMP-safe re-run changed the picture (raw:
`scripts/profile/results/tickacct_ab_2026-08-09.log`):

| getpid ns | pre-SMP-safe | SMP-safe |
|---|---|---|
| OFF (placement) | 1050.7 | 1026.5 |
| ON (tickacct) | 934.8 | 1031.0 |

tickacct's pre-SMP **−116 ns** win was the **emitter-closure construction** in
the old `poll(emitter)`, run every syscall boundary. The SMP-safe `poll()`
returns signals (no closure), so the **OFF** path gained that saving too — ON ≈
OFF now. Separately, the `SpinNoIrq` lock costs ~96 ns/syscall (ON 935 → 1031),
the price of SMP-correct accounting. **Net: tickacct is now perf-neutral; its
value is purely the correct uniform all-CPU accounting** (secondary CPUs
previously had no periodic tick accounting). Accounting stays exact
(`rusage_acct` PASS, syscall s_frac 0.68 both, within the Linux 0.72 band).

Possible future micro-opt (not pursued — the syscall gap is dominated by other
layers): a preempt-only spinlock (drop the IRQ-disable; same-CPU reentrancy is
already handled by `try_lock`-skip in the IRQ paths) could recover part of the
~96 ns, or a lock-free atomic/seqlock design for the hot counters.

## Board A/B RESULT (2026-08-09, RK3588, same HEAD, only `tickacct` differing)

`syscost 500000` + `rusage_acct 2`; Linux ref pinned A76/cpu4. Raw:
`scripts/profile/results/tickacct_ab_2026-08-09.log`.

| metric | Linux | OFF (placement) | ON (tickacct) | ON vs OFF |
|---|---|---|---|---|
| getpid | 152 ns | 1050.7 ns | **934.8 ns** | **−116 ns (−11%)** |
| pipe_wr | 560 ns | 5913.9 ns | 5844.1 ns | −70 ns |
| rusage user  cpu/wall · u_frac | 1.00 · 1.00 | 1.00 · 1.00 | 1.00 · 1.00 | = |
| rusage sysc  cpu/wall · s_frac | 1.00 · 0.72 | 1.00 · 0.71 | 1.00 · 0.72 | = (= Linux) |
| rusage verdict | PASS | PASS | PASS | = |

Two conclusions, both empirical:
1. **Accounting is EXACT.** tickacct's utime/stime are identical to the OFF path
   and match Linux (s_frac 0.72 = Linux 0.72, cpu/wall 1.00, no loss/double).
   FIX B's boundary `tick()` delivered the exact user/kernel split as designed —
   the review's HIGH split regression is gone.
2. **getpid −11% (−116 ns).** A real saving here — but see the SMP-safety
   section below: this −116 ns was the per-boundary emitter-*closure*
   construction, which the later SMP-safe `poll()` refactor removed from **both**
   paths, so tickacct ends up perf-neutral. This table is the pre-SMP-safe
   measurement; the honest final numbers are in the SMP-safety section.

The syscall gap to Linux (935 vs 152 ns) is still dominated by the layers below
(check_signals, dispatch, the SVC round-trip); tickacct is a correct, gated,
modest lever, not the headline. Ships OFF by default pending the SMP-safety
prerequisite (task #62).
