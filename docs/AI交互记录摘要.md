# AI 交互记录摘要

> 本文件是「AI 使用说明」第七节的附件，给出本工作各阶段使用 Claude Code 进行开发的脱敏记录摘要。完整的逐轮交互留存在队员一侧；整理时已对开发板凭据、网络地址、内部日志等敏感信息做脱敏处理，本摘要不含任何此类信息。

## 一、会话总览

开发跨越多个独立会话，按工作单元归并如下。每个单元都遵循同一条主线，即 AI 在队员给定的规格内产出实现与调试草稿，而设计取舍、正确性判据与是否采纳由队员决定，并以真机实测收口。

## 二、贯穿始终的协作方式

下列做法在各会话中反复出现，它们共同构成了「让 AI 产出可靠操作系统代码」这一问题的具体答案。

**规格先核验。**　多数会话都从同一步开始，即先让 AI 拿所给规格与真实代码、RK3588 手册及厂商驱动逐条对照，再动手实现。这一步多次查出规格中的错误，例如把用户态的版本查询误当作内核 ioctl、把某段 CPU 回退时延高估等，从源头避免了基于错误前提的实现。

**真机为准。**　许多内核问题只在真实硬件上暴露，性能与正确性主张一律以板上实测收口。队员在每一轮板上运行时亲自断电重启、复位串口、在镜头前放置目标，AI 不能代替这些动作；凡 QEMU 无法验证硅片行为之处，相关结论都明确标注为待板上确认。

**拒绝绕过，要求根因。**　队员多次驳回看似省事的绕过，例如以增大超时掩盖锁依赖、仅靠电源管理而不做完整时钟上电、为自测单开一个特性等，要求 AI 解释根因与影响面后再做正解。

**自我纠错与对抗式复核。**　AI 在过程中主动改正了自己写错的硬件寄存器取值，撤回了若干基于推断的过度断言，并以独立的复核流程主动尝试反驳自己的结论；一次板上中断诊断的结论被自身的探针数据连续推翻数次，最终以证据而非断言收尾。

**数值与署名的诚实护栏。**　报告与文档中的每一项数值在成文前都由独立流程对照原始日志核对；不同分辨率模型的两组数字分别与各自的 Linux 基线相比、不得拼接；贡献表只认按提交历史核实的真实作者；过程中出现的无法核实的表述被逐条删除。

## 三、脱敏与记录留存

逐轮交互记录留存在队员一侧，可按需提供。本摘要及随附材料在整理时已移除开发板登录凭据、内网地址与内部运行日志等敏感信息，相关位置以占位符代替。本工作不主张任何未经实测支持的结论；AI 加速的是规格之内的实现与调试，系统设计、正确性判据与采纳决定均由队员完成。
