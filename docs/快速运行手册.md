# 快速运行手册

本手册给出在无开发板与有开发板两种条件下编译并运行本工作的完整步骤。机器人应用与内核可分别构建，内核经 QEMU 即可验证功能，完整的相机到推理流水线需在 OrangePi 5 Plus 上运行。

## 一、环境与工具链

- Rust nightly-2026-04-27，edition 2024，见仓库根 `rust-toolchain.toml`；目标三元组 `aarch64-unknown-none-softfloat`。
- 全部构建、运行与测试经 `cargo xtask` 完成，实现于 `scripts/axbuild/`。
- 在 macOS 等无法本地交叉编译 no_std 的主机上，可用项目容器镜像 `ghcr.io/rcore-os/tgoskits-container:latest`（经 OrbStack 或 Docker）执行内核构建与 QEMU。
- 机器人应用为 aarch64 Linux（glibc）原生程序，需要一套 aarch64 Linux glibc 交叉工具链；预编译的 Rockchip 库为 glibc，不可使用 musl 工具链。

```bash
# Linux / 项目容器
sudo apt-get install gcc-aarch64-linux-gnu g++-aarch64-linux-gnu
# macOS
brew install messense/macos-cross-toolchains/aarch64-unknown-linux-gnu
```

## 二、无开发板：QEMU 与主机自测

内核在 QEMU 上即可验证功能与各项测试用例。

```bash
cargo xtask starry rootfs --arch aarch64   # 准备根文件系统（首次一次即可）
cargo xtask starry qemu   --arch aarch64   # 在 QEMU 上运行
```

机器人应用提供一个不依赖板子、相机与模型的主机自测构建，用于在任意主机与 CI 上复跑端到端基准。

```bash
cd apps/starry/orangepi-5-plus-tennis
cmake -S tennis-app -B tennis-app/build-host -DTENNIS_HOST_DRYRUN=ON
cmake --build tennis-app/build-host
./tennis-app/build-host/tennis_app --mode dry-run --duration-sec 5
```

自测以一段确定性合成场景驱动完整状态机，并打印作为强制交付物的 `TENNIS_BENCH_RESULT` 行。

## 三、构建内核

网球应用对应的内核构建配置为 `apps/starry/orangepi-5-plus-tennis/build-aarch64-unknown-none-softfloat.toml`，其中开启了 RKNN、RGA、JPEG 等加速器特性与全部八个核。

```bash
# 注意先解除 RUSTUP_TOOLCHAIN 环境变量，详见第六节
env -u RUSTUP_TOOLCHAIN cargo xtask starry build \
  --config apps/starry/orangepi-5-plus-tennis/build-aarch64-unknown-none-softfloat.toml
```

产物为 `starryos.bin`，经 `cargo xtask starry app board` 部署到开发板。

## 四、交叉编译机器人应用

```bash
cd apps/starry/orangepi-5-plus-tennis
./build-image-runner.sh
```

脚本自动探测交叉前缀（`aarch64-linux-gnu-`，否则 `aarch64-unknown-linux-gnu-`，亦可用 `CROSS_COMPILE=` 指定），以 Release 构建，产物位于：

```
tennis-app/install/rk3588_linux_aarch64/tennis_app/
```

其中含 `tennis_app` 可执行文件、`lib/librknnrt.so`、`model/` 与 `validation/`。`libstdc++` 与 `libgcc` 静态链接，glibc 保持动态（板上 glibc 版本须不低于工具链；若遇 `GLIBC_…` 运行期错误，改用容器工具链）。

## 五、开发板上部署与运行

应用二进制与内核分开部署。内核经 xtask 烧写，应用需预先装入板上根文件系统。

1. 在 Linux 主机上以 `./build-image-runner.sh` 构建。
2. 持有板子租约时，经 SSH 将 `install/rk3588_linux_aarch64/tennis_app/` 同步到板上 `/tennis_app`，随后 `chown root:root` 并 `sync`。`/tennis_app` 须含 `tennis_app`、`lib/librknnrt.so`、`model/`、`validation/`。
3. 实时模式还需板上存在 `libuvc` 并连接一只 UVC 相机；自测模式只需二进制与 `lib/librknnrt.so`。

经 xtask 部署内核并运行：

```bash
# 默认：有界自测烟雾测试，无需相机与模型
cargo xtask starry app board -t orangepi-5-plus-tennis

# 60 秒实时感知基准（需相机与模型）
cargo xtask starry app board -t orangepi-5-plus-tennis \
  --board-config configs/board-orangepi-5-plus-bench.toml
```

xtask 只部署内核，板子的上电与串口连接由持卡人在租约内操作。开发板地址与凭据等在本仓库文档中均以占位符表示。

## 六、常见问题

- **工具链被覆盖。**　若环境导出了 `RUSTUP_TOOLCHAIN`（例如固定为某个稳定版），它会遮蔽仓库锁定的 nightly 并使 `-Z` 选项失效。内核构建一律以 `env -u RUSTUP_TOOLCHAIN` 前缀执行。
- **模型路径。**　实时模式默认读取 `model/` 下的 RKNN 模型；路径缺失时应用打印 `rknn_init fail!` 并以非零退出。本仓库已随应用提供 480×640 与 640×640 两个网球模型权重。
- **基准与剖析。**　开发板上的流水线基准经 `scripts/profile/` 下脚本运行，逐帧 CSV 与逐阶段计数以纯标准库渲染为图，无需额外绘图依赖。
